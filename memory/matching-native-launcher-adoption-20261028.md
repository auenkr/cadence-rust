# Native Matching launcher adoption, 2026-10-28

Production remains on the configured legacy durable queue path in `launcher.rs` (`MatchingTaskStoreSource::ConfiguredDefaultStore`). Native production adoption is **not complete**. There is no new active native queue owner, and embedded/development behavior remains unchanged. Do not switch the production branch until the gaps below are resolved and validated.

Implemented, pending parent module registration and CI:

- `matching_launch_native.rs::assemble` builds a native semaphore service and native host over a caller-supplied fully configured native registry and configured byte semaphore store. It uses the same domain cache, live dynamic config, membership, and the runtime Matching shutdown state; callbacks for metrics are required. It attaches through `MatchingRuntime::with_native_host`, which calls `with_native_queues`. The caller must build the registry using `matching_runtime_native::native_queue_registry` and install its actual routing, scaler, refresh, metrics and fatal providers before assembly. No fallback provider is supplied. Register `matching_launch_native` in `lib.rs` before CI.
- The launcher opens the legacy and byte semaphore stores together via `open_configured_semaphore_stores`, and wraps both with the same production limiter. The native store is retained locally but not used while the legacy path is active.
- `MatchingRuntime` retains the host and native semaphore, opens native admission after membership startup, closes it at the existing post-drain shutdown transition, sweeps idle and non-owned semaphore buckets, joins the sweep task and stops all buckets. Existing native registry maintenance, domain notification, membership unload, and writer joins remain runtime-owned. Startup failure shutdown closes the native gate too.

Blocking work before the production switch:

1. `matching_runtime.rs::with_shard_distributor` constructs `QueueRegistryShardProcessorFactory` from a **legacy** registry and installs legacy `QueueOwnershipPolicy`; `with_noop_shard_distributor` also installs only legacy ownership policy. Implement native shard processor, native byte-preserving assignment checks, ownership and discovered router on the same registry/host, including empty namespace behavior. Both configured and no-namespace cases matter. Native host/control must receive that exact router, and executor lifecycle must remain runtime-owned.

Assemble the registry from configured `stores.native_task_store`, `matching_history`, cache, state, cluster, range and fatal sinks using `native_queue_registry`; install live membership, weak local native service forwarding, remote parent, partition refresher, scaler/isolation and observers. The registry's optional providers in `matching_registry_native.rs::with_local_poll_service`, `with_parent_router`, `with_membership`, `with_partition_refresher`, and `with_scaler_starter` must not be silently left empty. The other worker owns `matching_runtime_native.rs` and scaler integration; coordinate its evolving APIs.
3. Native host `NativeRequestMetric` and `NativeFailureMetric` in `matching_host_native.rs` carry only method/status; they lack domain, task-list, caller metadata, request latency and Go scoped tags. Registry metrics are also not installed by `MatchingRuntime::with_metrics` for a native registry. Implement full scoped metrics and timeout reporting against the existing Matching metric providers before wiring real callbacks; do not pass no-ops. Map byte fields without lossy conversion.
4. Connect `NativeFatalSinks` writer and reader to the same launcher fatal channel (`matching_fatal::MatchingFatal`, `launcher.rs::FatalExit`) and ensure SQL raw run IDs survive. The host assembly requires the existing quota and concrete poll observer providers. Confirm native transport dispatch for gRPC and Thrift/TChannel against the same host; listeners already select `Matching::native_service` in `grpc_matching.rs` and `thrift_matching.rs`.
5. Add bounded tests for actual startup failure, admission/drain, membership transfer, idle eviction, semaphore stop, configured persistence/limiter, routing, fatal propagation and metrics.
