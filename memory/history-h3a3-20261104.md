## Status

Implemented the decision-task add-event transition slice in Rust on branch

## Ported

- Decision scheduled and heartbeat scheduling: task-list selection, timeout,
  sticky-list use, duplicate scheduling validation, schedule IDs/timestamps,
  transient retries that avoid emitting repeated events, and buffered-event
  flush before scheduling.
- Decision started: scheduled/start event IDs, request ID and identity,
  current version, and retry behavior when a transient schedule needs to become
  a persisted schedule.
- Decision completed: validates schedule/start IDs, clears decision state
  before adding completion, reconstructs transient schedule/start events for
  retry attempts, records `last_processed_event`, and updates auto-reset point
  and binary-checksum state.
- Decision timed out and failed: start-to-close attributes, no-event repeated
  retry handling, failed-event reset attributes, attempt increment/reset, and
  reset workflow request tracking.
- Completion hooks, decision failure cleanup, and buffered-event flush support.
- Added the failed-event reset fields to the Rust API event attributes and
  preserved them through Thrift and protobuf conversions.
- Added unit coverage for scheduled, heartbeat/transient scheduling, started,
  completed, timed out, failed, reset-point/checksum updates, and resulting
  decision metadata.

## Remaining parity work

This is an event-transition slice, not complete History service parity. The
current state-only builder has no History task generator, mutability lifecycle,
shard/config/clock/metrics dependencies, or durable typed workflow execution
record. Therefore decision schedule/start task generation and its bypass flag,
mutability errors, workflow state transitions, critical-attempt metrics/logging,
resettable checks on reset points, and advanced-visibility search-attribute
writes/tasks still need the corresponding builder/service infrastructure.
Other decision APIs and manager paths remain out of scope here, including
first-decision scheduling, replicated transient scheduling, schedule-to-start
and reset timeouts, and replication-side decision transitions beyond the
existing H3a2 work. Retry/no-event branches need further Go parity tests.
