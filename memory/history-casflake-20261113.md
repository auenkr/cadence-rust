## 1. dbrestart recovery flake (run 43411166710 attempt 1)
- Evidence limits: attempt 2 overwrote the artifact `history-mixed-gate-cassandra-tchannel`; only the 100-line gate.log tail of attempt 1 survives. It shows rust-history `History engine state changed: stopped` (11:09:41) followed only by domain-failover callbacks (no `Created new history shard item`) and the SDK recover steps failing (`workflow-started-during-failure`, `signal-two`, `complete-signal`, `raw-poll-new-decision`).
- Candidate root cause (code review, not reproduced): `ShardRegistry::create_entry` close callback removed whatever cell was registered for the shard id; Go `removeEngineForShard(shardID, shardItem)` removes only the item owning the closing context. After DB-restart LWT timeouts the old context closes (ownership lost -> `close_shard`, callback runs on a spawned thread); a late callback could remove and stop the freshly created healthy engine for the same shard, leaving the shard without an engine until the next request recreates it (matches "engine stopped" tail with no recreate).
- Fix: `rust/crates/cadence-history/src/wiring/assembly/controller.rs` `remove_matches` (Weak ptr_eq of the ShardContext); unit test `late_close_callback_keeps_uninitialized_or_unknown_successor`.
- Proof (head 1b-see below): cassandra/tchannel/two_history=false runs 43422050490 43422062378 43422074180 and cassandra/grpc/false runs 43422085371 43422096243 43422108718: all success (6/6). Honest caveat: flake was 1 in ~12 historically, so 6/6 is supporting, not conclusive; the harness also needs per-attempt artifact names to keep attempt-1 evidence (not changed).
