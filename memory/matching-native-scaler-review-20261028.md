# Native Matching scaler review, 2026-10-28

Scope: `matching_scaler_native.rs`, compared with Go `adaptive_scaler.go`, `isolation_balancer.go`, and the legacy Rust scaler and registry loop. No Cargo, rustfmt, Go validation, CI dispatch, commit, or push was performed in this review.

Changes: sample execution settings after the timer fires (the timer interval is sampled before the wait), preserve parse error bytes through the native status helper, and determine a locally described partition's write status from that partition's reported configuration, treating absent config as writable as Go does. Previously the fallback drain check consulted the proposed write map and could prematurely drain a partition. Fix the group goal upper bound for zero write partitions, remove ignored `Option` map calls and unused private helper, and use struct initializers in tests. Added tests for reported write status and byte-preserving balancing moves. A `starter_with_metrics` observation callback exposes calculation, drain, request, and failure events; the existing starter remains compatible and uses a no-op callback.

Review notes and remaining gaps:

- Registry owner stop/drop invokes `ScalerDaemon::stop`, aborting the spawned future, including pending sleeps, describes and updates. The registry remains weakly held between ticks. There is still a check/get race around cached owner lookup; the owner abort is the primary cancellation mechanism and must be verified in CI with unload/reload and blocked remote calls.
- Isolation aggregation sums QPS and ORs pollers over read partitions and resets all sustains on collection failure. It currently fetches sequentially; Go fetches concurrently and waits for all requests, so latency and failure timing differ. The snapshot config is sampled once per tick while Go dynamic properties can change during an operation. Local group metrics only enumerate configured groups; verify this matches actual Describe responses, including arbitrary byte names.
- Disabled scaler/cache skips a tick without resetting sustain state, as Go does. Disabled isolation resets balancer after successful collection. Shrink stops on the first nonempty, writable, or failed trailing describe, and uses reported config rather than proposed config. Remote callback must return reported write membership and apply the configured empty-check semantics.
- The metrics callback is an integration seam, not full Go metrics parity: the default starter drops observations, no production metrics adapter is wired here, and group polling/scale and partition scale counters are not exposed. Calculation observations permit gauges and rebalance accounting, but cannot reconstruct all sustain-trigger counters. Go event/log parity also remains incomplete.
- Balancing retains byte keys and Go's greedy algorithm for normal dense partition maps. Tie ordering and floating-point accumulation may differ with Go map iteration; the existing no-movable-group guard deliberately avoids a Go infinite loop in an inconsistent configuration. Nonpositive dynamic limits differ from Go in existing shared helpers (`number_of_partitions` and group divisor protection). This review does not establish exact parity for invalid configuration.
- Production must wire a byte-preserving config provider and owner-routed remote describe, register the scaler and metrics hook, and validate persistence, lifecycle, and mixed Go/Rust restart and SDK behavior. These dependencies are outside the owned files and have not been verified here. Tests and compilation require the parent-controlled CI gate; no passing result is claimed.
