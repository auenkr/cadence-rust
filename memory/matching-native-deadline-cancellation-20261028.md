# Native Matching admission deadlines — 2026-10-28

Go `getOrCreateTaskListManager` passes the handler context to shard admission and starts an accepted manager with `context.Background()`. Native registry `get_with_deadline` bounds ownership admission and the caller's wait for startup, checks expiry before dispatching startup, and leaves already dispatched owner work detached. Add and poll pass their request deadlines; query already encloses its whole engine future in its own deadline. Describe, cancel, update and refresh are bounded at the service boundary because their engine control interface has no deadline argument. Context expiry is mapped to Internal, consistent with the Go handler's untyped context error; semaphore and normal long-poll result paths are not wrapped by a generic timeout.

Regression code calls actual native AddDecisionTask, PollForDecisionTask, QueryWorkflow and DescribeTaskList with pending shard admission and short RPC deadlines, checks the callback was entered and never completes after release, and checks no owner was published or storage lease created. Actual native AddDecisionTask also exercises injected handler panic and forwarded metric count on quota rejection. These tests do not cover every poll or control variant, and have not yet been validated by CI. No local Cargo, formatting, Go or heavy validation was run. Parent must run workspace and mixed Go/Rust SDK, restart and recovery gates before any parity claim. The known base launch/scaler argument compile mismatch is owned by the activation worker.
