# Matching raw source-domain lookup ordering (2026-10-29)

Follow-up to 06f4094a8: raw cache keys are checked before persistence and remain byte-exact. On a miss the rate-limited source now receives the raw bytes and parse mode, so rejection occurs before SQL's MustParseUUID behavior. An admitted malformed SQL ID yields the captured-panic status with Go byte quoting. The metered Go wrapper increments its request counter before invoking the store; unwinding skips latency and error metrics, which the Rust wrapper now models. The SQL 38-byte form permits arbitrary outside bytes; when those are non-UTF8 only the accepted ASCII UUID body is passed to the string-based source, while cache identity remains unchanged.

Go references: common/persistence/wrappers/{metered,ratelimited}/domain_generated.go, metered/base.go, sql/sql_domain_store.go and nosql/nosql_domain_store.go; Cassandra SelectDomain binds the original ID to gocql. Rust has a Cassandra metadata source adapter; its string-based API and uuid parser do not reproduce arbitrary non-UTF8 Go strings or necessarily all gocql parse/error details. The default raw adapter now reports this conversion limitation as an internal source error instead of fabricating a BadRequest UUID error; Cassandra raw-byte error parity remains unverified. No claim is made that Cassandra metadata itself is unsupported.

Regression tests cover exhausted limiter before malformed parse, admitted malformed non-UTF8 panic and its request-only metrics, and admitted 38-byte non-UTF8 wrapper reaching the source. These tests have not been run or formatted: parent owns CI and formatting under the task instructions. No mixed-cluster behavior has been validated here.
