# History dynamic config parity audit (2026-11-21)

Scope: every `dynamicproperties.*` key read by Go history (`go/service/history/config/config.go` New: 269 identifiers; whole `go/service/history/` non-test: 289 identifiers incl. helper types) vs Rust (`rust/crates/cadence-history/src/config.rs`, generated by `memory/tools/gen_history_config.py`, plus `config_collection.rs`).

Method: script mapped Go constant -> KeyName/DefaultValue from `go/common/dynamicconfig/dynamicproperties/constants.go`, then grepped the key string in rust/ and compared the default in `config.rs` (251 `dc.prop*` calls).

Results:
- Missing keys: **0** (every Go history key string present in rust/).
- Default mismatches: **0 semantic**. 75 textual differences are only notation (`time.Minute*5` vs `Duration::from_nanos(60_000_000_000*5)`, `UnlimitedRPS` vs `i32::MAX`, `ConvertIntMapToDynamicConfigMapProperty` vs `int_map(..)`, Go trailing comments, `GetDefaultIndexedKeys()` vs `default_indexed_keys_map()`).
- Filters: Rust uses `prop` / `prop_domain` (and shard/tasklist variants) generated from the same Go getter names.
- Remaining Go identifiers in grep (GetBoolPropertyFn, FilterOption, IntKeys, ...) are types/helpers, not keys.

Conclusion: no keys needed porting; no code change made. CI/gate runs below validate the branch head (identical to master code) .
