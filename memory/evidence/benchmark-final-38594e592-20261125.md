## Notes
- A/A noise (control vs rust, identical binary): throughput within about +/-2.5%; latency within about +/-6% (c64 p95/p99 up to ~+5%). Go-vs-Rust deltas of that size are noise.
- c1 p95 ~100 ms under the default config (all arms incl. A/A, MySQL and Postgres) is the shared 20 rps task-load limiter; with the limit raised (B) rust c1 p95 is ~32 ms. Go->Rust c1/c16 p95 in A (+12%/+2%) is within limiter-dominated noise.
- Go arm at c64 is much worse on MySQL (A 26.7 wf/s, B 21.5) than rust/control (~71/60), so Go->Rust c64 MySQL deltas (+166%/+181%) are large and run-dependent; PostgreSQL (C) gives the more conservative c16/c64 deltas (+47%/+59% throughput, p95 -39%/-34%).
- Rust FE/MT use roughly 40% less peak anon memory and about half the CPU-seconds of Go; Rust history CPU is roughly 40-80% lower.
- Soak: all arms degrade over the 12000-request run (latency grows from the first to the last third). Rust and control drift similarly (p50 +6..+19%, p95 -16..+68%, differing sign between the two replicates, i.e. noisy); Go p50 drifts +21..+24% and p95 +15% in both. Throughput: rust ~51-55 wf/s vs Go ~26 wf/s (roughly 2x) in both replicates; no Rust-specific degradation versus the A/A control.
- Raw artifacts: `frontend-matching-paired-benchmark` in each run (3-day retention).
