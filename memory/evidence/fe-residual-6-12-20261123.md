## #6 `unknown: ` prefix on the wire
- Go: `go/client/clientBean.go:144,160` is a plain `fmt.Errorf("unknown cluster name: %v with given cluster client map: %v", ...)`. The proto mapper sends it as `status.New(Unknown, err.Error())`, so the message is bare. The Thrift path already sent the bare message.
- Rust: `CadenceError::Unknown` Display adds `unknown: `. `wrappers/grpc.rs::error_message` used `to_string()`, so the gRPC status message carried the prefix. It now returns the inner message for `Unknown`.
- Map text: Go `%v` of the map of pointer clients prints heap addresses (`0xc000...`), which are not reproducible. Rust keeps the `map[name:0x0 ...]` shape (sorted names). That is the observable shape, so no new text was invented.
- Test: `unknown_error_message_has_no_display_prefix` (grpc.rs).

## #12 HTTP/JSON raw-history token presence
- Go: `admin/handler.go` branches on `request.NextPageToken == nil`. `encoding/json` decodes an absent field or `null` to nil, and `""` to an empty non-nil slice.
- Rust: `cadence-service-core/src/admin.rs` now deserializes via `RawHistoryJsonRequest { request, token_present }`. Absent or `null` means not present. `""` means present but empty, so it reaches token decoding as in Go. `null` is stripped before the typed decode, since the existing `[]byte` decoder rejected it. The yarpc bridge passes `raw_history_token_present(body)`. No `cadence-api` type change.
- Tests (admin.rs `raw_history_json_presence_tests`): absent/null, empty string, non-empty token.
