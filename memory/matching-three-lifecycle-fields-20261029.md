# Matching three lifecycle settings: bounded source audit

Base: `530953ac7` (origin/t3/review-quota-integration). This is a source audit of only these three fields; it is not Matching parity acceptance. Existing context: `matching-config-property-audit-20261021.md`, `matching-current-config-reconciliation-20261027.md`, and `matching-runtime-owner.md`.

| Field | Go binding and actual use | Native configured path and classification |
| --- | --- | --- |
| `IdleTasklistCheckInterval` | `matching.idleTasklistCheckInterval`, default 5m, domain name/task-list name/type filters (`go/common/dynamicconfig/dynamicproperties/constants.go:5744`, `go/service/matching/config/config.go:201`). Manager obtains domain name from cache and captures it with queue name/type (`task_list_manager.go:170,1033-1048`), then reads once per manager (`:217`). `liveness/liveness.go` initializes last event, starts ticker at TTL/2, expires at elapsed >= TTL, and asynchronously stops manager. `task_list_manager.go:561,690` marks unforwarded adds and polls alive. | `grpc_matching.rs` configured provider resolves UUID to name and reads `task_list_duration` with queue/type; `matching_registry.rs` samples once per owner and schedules per-owner liveness; `cadence-common/src/liveness.rs` uses Go's wrapping elapsed comparison. Existing `matching_idle_interval_is_sampled_for_each_owner_only_at_creation` and idle pump/mark tests cover timing paths. Corrected invalid TTL clamp and missed-tick overflow below. Name lookup is performed during that single sample; unlike Go's required cache lookup it falls back to unfiltered if unavailable. This source-level discrepancy remains, including non-UTF8 task-list handling owned by the raw-byte integrator; do not claim complete filter parity. |
| `MaxTasklistIdleTime` | `matching.maxTasklistIdleTime`, 5m, same three filters (`constants.go:5750`, `config.go:202`). Production Go tree search for `MaxTasklistIdleTime` finds only declaration/key metadata, `Config`/`TaskListConfig` declarations, binding and closure at `task_list_manager.go:1050-1052`; there is no invocation of that closure or other production consumer. | `matching_config.rs` exposes a reader, but native lifecycle does not consume it. Correct scope: no idle behavior should be added for this field. Zero, negative and extreme values have no lifecycle effect in Go because the closure is never called. |
| `ShutdownDrainDuration` | `matching.shutdownDrainDuration`, global/unfiltered, zero default (`constants.go:5762`, `config.go:216`). `service.go:138-154` evicts self, evaluates property at shutdown, sleeps, closes stop channel, stops handler and resource. Go `time.Sleep` returns immediately for <= 0. | `matching_runtime.rs::live_shutdown_drain_duration` reads live unfiltered on shutdown; `drain_service` evicts before sampling and skips zero duration. Negative is clamped to zero, preserving no-wait behavior. Positive i64 nanoseconds, including maximum, are retained; malformed/out-of-range text falls back to default via dynamic config parser. Existing `shutdown_drain_provider_reads_live_unfiltered_value`, `shutdown_uses_drain_duration_updated_after_runtime_startup` and `shutdown_drain_runs_membership_evictor_before_live_drain_read` cover sampling/order. |

Go file/configstore clients parse duration strings with `time.ParseDuration`; dynamic-property read errors fall back to the key default (`go/common/dynamicconfig/config.go:335`, `file_based_client.go:173`, `configstore/config_store_client.go:272`). Native string parser and typed runtime handling are in `cadence-persistence/src/dynamic_config.rs::{task_list_duration_bytes,duration}`. All representable positive Go durations use a positive TTL/2 except 1ns. Go's production ticker rejects TTL <= 1ns (including negative and zero). Previously native clamped those to 1ns and created a busy/unloading owner. Native now rejects creation with Internal status instead; Go panics in `NewTicker`, so process-failure semantics are still different and not claimed equivalent. The owner may already have opened its durable queue before rejection. Positive maximum TTL retains its half period. Delayed idle checks previously narrowed missed tick count to u32 and could wrap or overflow; scheduling now computes the next boundary with a remainder. `idle_ticker_rejects_nonpositive_go_period_and_handles_extremes` and `invalid_idle_interval_does_not_create_an_owner` are bounded regression sources.
