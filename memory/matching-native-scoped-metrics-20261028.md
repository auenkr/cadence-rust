# Native Matching scoped metrics — 2026-10-28

Matching remains incomplete. This change scopes scaler observations per root key and emits the existing MatchingMetrics scaler gauges, scale/rebalance/drain/update counters and isolation-group transitions/partition gauges. The registry starts scalers only for normal root owners; the normal kind is derived from that condition. The scoped provider resolves domain names via the cache, with the same unknown fallback as the registry. Isolation keys remain GoString until the existing string-valued metric sink boundary. That sink converts invalid UTF-8 lossily, so byte-distinct non-UTF-8 metric labels can still collide; queue routing and state remain byte-valued.

Integration APIs:
- `matching_scaler_runtime_native::scoped_scaler_metrics(MatchingMetrics, Arc<MatchingDomainCache>) -> ScalerMetricsProvider`; `attach_scoped_native_scaler(registry, state, cache, membership, router, provider)` and `starter_with_metrics_provider(config, describe, provider)` create one callback per actual `TaskListKeyBytes` root. Existing unscoped APIs remain for old callers.
- `attach_live_native_registry(registry, state, cache, membership, router, metrics)` now installs that real scoped provider and the registry poll observer itself; the old scaler callback argument is removed.
- `PollObserverFactory` now accepts `(domain: &GoString, list: &GoString, task_type: i32, task_list_kind: i32, isolation_group: &GoString)`. Kind is the persistence kind produced from the actual request. `metrics_poll_observer_factory(metrics, cache)` creates the real sink-backed factory.
- **Required host integration (outside owned files):** `NativeMatchingHost`'s `NativePollContext` implementation must add `fn observer_with_context(&self, domain: &GoString, list: &GoString, task_type: i32, task_list_kind: i32, isolation_group: &GoString) -> Option<Arc<dyn NativePollObserver>> { self.engine.observer_with_context(domain, list, task_type, task_list_kind, isolation_group) }`. Without this, the trait compatibility default invokes its old observer method and no configured engine observation is emitted. The launcher must pass `Some(metrics_poll_observer_factory(metrics.clone(), cache.clone()))` to host assembly. The older configured assembly uses an unscoped callback and must be updated to use `attach_live_native_registry` or the scoped scaler helper. Do not activate until these changes are integrated.
- The existing NativePollObserver `poll_match` interface lacks task partition isolation data and the host adapter passes None to MatchingMetrics; poller isolation is retained in the context but isolation-match metric emissions still require a separate dispatch/observer interface change. The existing metric sink uses string labels and does not preserve invalid UTF-8 labels.

Source regressions inspect emitted scaler names, domain/queue/group tags and normal versus sticky poll tags. They do not establish mixed-cluster parity or lifecycle behavior. No local Cargo, rustfmt, Go, or heavy tests ran; `git diff --check` passed. Parent must complete the host/launcher integration and fresh workspace and same-pin mixed SDK/recovery gates.
