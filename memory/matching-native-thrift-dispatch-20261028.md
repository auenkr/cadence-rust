# Native Matching Thrift dispatch — 2026-10-28

Added a private child of `thrift_matching.rs` exposing `dispatch_native_with_context`. All ten methods in the pinned MatchingService Thrift descriptor call `cadence_proto::native::NativeMatchingApi` through existing byte-valued request and response adapters. Request normalization uses the same descriptor schema as the legacy path; deadlines, inbound context, poll budgets, Meta and nil-request panic/admission behavior reuse the existing transport helpers. Ordinary non-nil request data never converts through the UTF-8 protobuf model.

The dispatcher currently accepts the existing Matching lifecycle handle alongside the native service. The launcher must construct these with the same real lifecycle/config dependencies and route HTTP/TChannel calls to this function before production adoption is established. Existing routers and TChannel entrypoints still use legacy dispatch. This commit is a callable adapter, not a production switch.

Typed raw error envelopes are retained in a private binary status marker for in-process Thrift mapping. This keeps invalid-byte QueryFailed errors classified as QueryFailed rather than falling back to BadRequest when grpc-go suppresses the details header. The gRPC wrapper removes the private typed marker before transmission, preserving Go's grpc-message/details behavior. The Thrift mapper decodes error string fields as protobuf bytes and retains raw domain/cluster/version/ownership fields. Its returned String summary is transport diagnostic text; exception body fields preserve bytes.

Added tests for all descriptor methods reaching native dispatch, raw domain/workflow/run/task-list bytes and deadline on adds, raw QueryFailed classification/message, and version error bytes. Extended the existing served gRPC regression to assert the typed marker does not leak. Tests are unverified; no local Cargo, Go or rustfmt ran. `git diff --check` passed. Parent-owned fresh CI and eventual mixed Go/Rust transport gates remain required.
