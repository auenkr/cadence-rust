# Frontend async workflow publisher: implementation slices (2026-11-02)

Bounded source audit for production `StartWorkflowExecutionAsync` and `SignalWithStartWorkflowExecutionAsync`. Current tree rechecked: `handler_workflow.rs` already validates, encodes, and calls optional `AsyncWorkflowPublisher`; it returns an empty success only after publish succeeds. `workflow_backend::build_workflow_api` currently never calls `.with_async_publisher(...)`, so production has no publisher. Existing trait and `AsyncWorkflowMessage` are production-visible but only test implementations exercise publication. This is Frontend-only; do not involve Worker/History migration.

## Go behavior and wire contract

Sources: `go/service/frontend/api/handler.go` methods at ~1601 and ~2216; producer selection `api/producer_manager.go`; queue/provider stack `go/common/asyncworkflow/queue`, `queue/provider`, `queue/kafka/queue.go`, `common/messaging`, and config `go/common/config/config.go:AsyncWorkflowQueueProvider`.

- Reject during shutdown (`validate.ErrShuttingDown`); run the same synchronous Start or SignalWithStart validation before queue lookup, preserving Go validation/error ordering.
- Resolve domain through domain cache; domain `AsyncWorkflowConfig.Enabled` must be true or BadRequest `async workflow is not enabled for domain <domain>`. Use `PredefinedQueueName` if set, else provider `GetQueue(QueueType, QueueConfig)`; errors propagate.
- Cache producers by queue ID (5-minute TTL, max 100); producer creation uses queue provider with logger/metrics. Kafka provider creates a synchronous Sarama producer with successes enabled and wraps it with topic-tagged metrics.
- Encode the *async wrapper request* as versioned ThriftRW, not JSON. Go's codec emits leading version marker `0x59`; encoding name is `thriftrw`. Existing Rust `handler_workflow_async.rs` does this and tests round-trip fixture-compatible payloads.
- Queue message fields: partition key = embedded workflow ID; type 0 for async start, 1 for async signal-with-start; header bytes preserve original RPC headers; payload is versioned ThriftRW; domain selects queue and is not a message field. Producer publish failure is returned to caller; success is empty response. Go records per-operation frontend metrics and async payload byte size; Rust's current encoder/publisher seam has no production metric instrumentation yet.

Domain async configuration already persists in Go SQL/Cassandra and has admin get/update APIs (`AsyncWorkflowConfiguration`, including enabled, queue type/config and predefined queue name). Rust API models exist. Rust production domain lookup is installed, but there is no discovered Rust async queue/provider/Kafka producer crate or production async queue config path. Rust has Kafka/messaging infrastructure elsewhere only if reusable; verify before choosing dependency (no dependency should be added blindly).

## Acceptance limitations / failure semantics

Do not treat handler unit tests or a fake publisher as service completion. A successful async RPC means broker publish acknowledged, not workflow started. Publish errors must return to SDK; never return empty success before ack. Retries can duplicate messages depending on broker delivery and client retry; preserve Go key/type and let existing Go consumer semantics define dedupe (inspect `go/common/asyncworkflow/queue/consumer/default_consumer.go` in implementation). Recovery evidence needs broker restart/reconnect or Frontend restart and proof that acknowledged messages are consumed exactly as Go handles them. Validate first in the current mixed cluster with Rust Frontend and Rust Matching; no Worker/History changes.

## Mixed async acceptance (2026-11-03, branch `frontend-async-gate`)

Gate: `frontend-mixed-gate.yml` mysql lane with `kafka=true` (Rust Frontend + Rust Matching, Go History/Worker; no Go Frontend/Matching). Lane starts `apache/kafka:3.8.0` (KRaft, plaintext, `--memory 1g --cpus 1`, topic `cadence-async-gate` with 3 partitions created by the gate, extra INTERNAL listener for admin tooling). Domain async config set via `cadence admin async-wf-queue update` (predefined queue `gate-async-queue`, defined in both Go and Rust `asyncWorkflowQueues`); the Go Worker's async consumer manager consumes it. Driver `FE_MODE=async` (`tests/frontend-gate/async.go`) uses SDK `StartWorkflowAsync` / `SignalWithStartWorkflowAsync`.

Bugs found and fixed (Rust):
1. Admin `GetDomainAsyncWorkflowConfiguraton`/`Update...` handlers used the in-memory store, not the persisted domain manager, so the Frontend publisher saw the domain as disabled. Now `FrontendDomainManager::{async_workflow_config,update_async_workflow_config}` (persisted, config version +1).
2. Domain config blobs (async config, bad binaries, isolation groups) were written without Go's `0x59` thriftrw version byte; Go's domain cache refresh failed (`Invalid binary encoding version`) and broke all Go services. `thrift_blob` now prefixes 0x59.

Steps proven (all `ok`): async start executes (workflow completes), async signal-with-start executes (signal delivered, completes `final:one`), invalid workflow -> BadRequest, domain without async config -> BadRequest `not enabled`, broker stopped -> async start returns an error (never success), broker restarted -> async start accepted and executes (rskafka reconnects), errored start never executed; all three services alive afterwards.
