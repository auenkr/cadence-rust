# Native Matching shard runtime, 2026-10-28

Partial implementation only; configured shard distributor is NOT ready for native launcher adoption. No local Cargo, formatting, builds or tests were run. Parent owns Actions validation and launcher assembly.

`matching_runtime.rs` now installs a raw-name native ownership policy for the no-op executor, including live percentage/short-lived exclusion and the no-local-processor result. Empty namespaces in `with_shard_distributor` now take that same no-op path. The bounded `native_noop_policy_refuses_raw_eligible_names_and_reads_live_config` test checks invalid UTF-8 error details and cached/noncached exclusion after a dynamic percentage change; it is unverified.

Blocking production work: `matching_shard_distributor.rs` currently defines `ShardProcessorFactory::create(String)` and `ExecutorRpc::heartbeat` over generated string-keyed messages (lines 81-90). Its `ExecutorState` uses `HashMap<String, ...>`; `get_shard_process`, `heartbeat_request`, `update_assignments`, and `start_processor` use UTF-8 strings (around lines 610, 812, 851, 902, 926). The generated executor.proto heartbeat uses string-keyed maps (lines 34-39, 66-68). Arbitrary Go string bytes therefore cannot pass through assignment, reports, or revocation. Spectator raw-byte support alone does not solve this. Correct integration needs a raw protobuf heartbeat implementation with byte-keyed map-entry messages, byte-keyed executor state and processor callbacks, byte lookup and not-found handling, preserving legacy adapters and lifecycle, and raw assignment/revocation/replacement tests. These changes are outside this worker's assigned files; a string conversion here would violate the user's explicit no-loss requirement.

`matching_runtime.rs::with_shard_distributor` still selects the legacy queue factory and requires `self.registry`; it must select a native factory and raw lookup when `native_registry` is present. Native synchronous ownership policy alone cannot reproduce the async `GetShardProcess` heartbeat-on-miss: `matching_registry_native.rs::check_task_list_ownership` is synchronous, and `matching_host_native.rs::check_owned` calls it. The host admission path needs an async raw lookup before snapshot checks, preserving non-not-found errors and shutdown behavior.

Exact router propagation is also outstanding: native host constructs control and engine contexts with immutable router options (`matching_host_native.rs::assemble`, `matching_control_context_native.rs` and `matching_engine_context_native.rs`), while the registry's `parent_router` is an unshared builder option (`matching_registry_native.rs:308,654,2169`). Runtime installs its router after native service construction. These need a shared live router slot and registry forwarding adapter using the same router, including empty namespaces. Avoid adopting the configured native launcher until all these paths and mixed Go/Rust failure/recovery gates pass.
