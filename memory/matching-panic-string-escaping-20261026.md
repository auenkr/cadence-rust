# Matching panic string quoting parity (2026-10-26)

- Scope: `matching_panic` string panic payloads, including malformed SQL DomainUUID panic text from `matching_domain_uuid`; Thrift classification and status mapping are not changed.
- Concrete mismatch: for a string payload containing NUL, Go `fmt.Errorf("panic object is not error: %#v", value)` uses `strconv.Quote` and emits `\\x00`; Rust `Debug` emitted `\\0`. That changes gRPC Unknown message text and the corresponding Thrift/TChannel unexpected-system-error text (0x05).
- Source checked without running Go: host Go source `/usr/lib/go/src/strconv/quote.go` (`Quote` calls `quoteWith(... false, false)`; `appendEscapedRune` uses `IsPrint` and Go escape spellings); `/usr/lib/go/src/strconv/isprint.go` (`IsPrint` ranges); `/usr/lib/go/src/unicode/graphic.go` (L/M/N/P/S plus ASCII space definition). `go.mod` pins `github.com/google/uuid v1.6.0`.
- Rust change: string panic payloads now use Go's quote escape spellings and the exact generated `isPrint16`/`isNotPrint16`/`isPrint32`/`isNotPrint32` tables from the checked-in Go 1.25.14 `strconv/isprint.go`. The lookup mirrors `strconv.IsPrint`, including combining marks, C1 controls, separators, format characters, soft hyphen, and unassigned code points. Non-string panic payload placeholder is unchanged. Unknown status / Thrift 0x05 path is unchanged.
- Unit cases cover NUL, BEL, BS, FF, LF, CR, TAB, VT, DEL, C1 NEL, printable Latin text, combining mark, NBSP, U+2028, zero-width format, soft hyphen, an unassigned code point, quote, and backslash. Cases were derived from source semantics; no local Go runtime, Cargo, rustfmt, or service runtime was used.
- First CI attempt: run https://github.com/auenkr/cadence-rust/actions/runs/40376319612, head `07b33d4f5d8046d973334f51ce43efad68aa7779`, failed one test because the test expected Go's `\\u00ad` for U+00AD. Source `appendEscapedRune` first selects `\\x` for all non-printable runes below U+0100; expected output corrected to `\\xad`. Clippy and formatting had passed. The implementation is now table-exact, rather than a partial Unicode-category approximation.
