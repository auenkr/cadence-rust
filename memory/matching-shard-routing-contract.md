# Matching shard-distributor ownership routing contract

Source audit of Go `common/membership/sharddistributorresolver.go`, `tasklist_differentiator.go`, `cmd/server/cadence/server.go:307-327`, and Matching `handler/engine.go:319-350, 1703-1705`; compared with Rust `matching_membership::Membership` and `matching_shard_distributor::TonicSpectator`.

## Go behavior to preserve

- The server wraps only the Matching service's hash-ring provider with `NewShardDistributorResolver`; history and other services retain their existing providers. The resolver reads the onboarding percentage and short-lived-task-list exclusion switch on every lookup.
- `TaskListExcludedFromShardDistributor` excludes when (a) short-lived exclusion is on and the name contains any case-insensitive ASCII UUID-shaped substring (`8-4-4-4-12` hex digits), or (b) `farm.Fingerprint64(name) % 100 >= percentage`. Percentage is converted from signed Go `int` to `uint64` before comparison; preserve that conversion for out-of-range values.
- Excluded names and a nil spectator use the existing ring. Eligible names with a spectator query `GetShardOwner` using an independent 1-second background timeout. Spectator errors propagate; they do not fall back to the ring. Go's resolver does not cache converted `HostInfo` objects; the spectator client's own cached namespace ownership is used.
- Shard-owner metadata recognizes `tchannel` and `grpc`. Each is parsed as unsigned base-10 with a 16-bit bound; missing/malformed values are omitted without failing the lookup. `hostIP` is required. The returned primary address is `net.JoinHostPort(hostIP, tchannelPort)`, where a missing or malformed TChannel port becomes `0`; identity is `ExecutorID`; named ports contain only successfully parsed values.
- `LookupN`, `AddressToHost`, subscriptions, membership snapshots, counts, Start, Stop and Refresh all continue to delegate to the ring. Routing path metrics distinguish `hash_ring` and `shard_distributor` lookups.
- In Matching manager creation, an excluded task list bypasses shard-executor assignment and uses local hash-ring ownership. An eligible list must have a local shard processor to reuse/create its manager; assignment errors are treated separately by `errIfShardOwnershipLost`.

## Rust boundary

`Membership` exposes an atomic current Ring snapshot through synchronous `owner(key)` and can update it via `replace`; `TonicSpectator::get_shard_owner(key, deadline)` already serves its cached snapshot and retries the real shard-distributor RPC for a cache miss. Existing Matching queue APIs and `Membership` checks are synchronous. This routing implementation is therefore a standalone async adapter over those actual providers: it returns the selected endpoint and routing path, and leaves handler/runtime wiring for a later change that can await it. It does not alter the synchronous membership API or invent queue assignment state.

## Implemented source checkpoint

`MatchingShardRouter` is an async, injectable adapter using `Membership` for the live Ring snapshot and `TonicSpectator::get_shard_owner` for cached/RPC shard ownership. Its property closures are read per lookup; it returns `ResolvedHost` plus `RoutingPath`, and typed errors retain the attempted path for later metric accounting. Ring-only `resolve_n`, `address_to_host`, `members`, and `member_count` mirror the corresponding Go wrapper methods. The small crate-private `Membership::{owners_n, owner_by_address, hosts}` additions expose the same current snapshot; Membership lifecycle and snapshot replacement remain owned by the existing Matching provider. It does not change the synchronous queue membership API or wire runtime/handler paths. The router does not cache converted HostInfo; repeated eligible lookups invoke the spectator boundary, whose existing Tonic client supplies its own cached ownership snapshot.

The source test module contains FarmHash modulo/boundary vectors (including Go's `my-task-list` modulo-100 value), case-insensitive UUID substring and partial UUID cases, dynamic onboarding/exclusion changes including Go's signed-int to uint64 cast behavior, live Ring replacement, missing-spectator and excluded Ring fallback, eligible spectator endpoint conversion, 1-second deadline propagation, errors without fallback, invalid/missing ports, IPv6 host joining, Ring-only multi-host/address methods, and empty-Ring typed errors. Go's `NewShardDistributorResolver` wrapper also delegates Start/Stop/Subscribe/Unsubscribe/Refresh; lifecycle and subscriptions remain with Matching's existing membership provider in this bounded async router and need integration-level treatment if those generic resolver surfaces are ported later.
