# Matching three duration settings: source map and candidate

Base `fc9552b7a60fd5a410cd59ee0e5aa68577a7a623` (origin/t3/matching-reader-rawbyte-review). This is a source audit and unvalidated candidate, not a parity or CI pass. No Cargo, Go, runtime validation or Actions dispatch was performed. Integrate on an immutable SHA and run hosted `cadence-matching` clippy/tests, then fresh-target workspace clippy/tests and mixed Go/Rust gates with binary SHA256. In particular run `forward_state_samples_poll_and_task_waits_independently`, native writer tests, native dispatch/reader tests, and configured RPC forwarding/reload tests. Add native configured integration tests for different simultaneous task/poll settings, filtered domain/task/type, cancellation, timeout saturation and reload; the new focused test alone does not establish end-to-end behavior.

Go authority: `go/service/matching/config/config.go` NewConfig installs `GetDurationPropertyFilteredByTaskListInfo` for all three; `go/common/dynamicconfig/dynamicproperties/constants.go` defines `matching.appendTaskTimeout` 5s, `matching.localPollWaitTime` 10ms, `matching.localTaskWaitTime` 10ms, each filtered by DomainName, TaskListName and TaskType. `tasklist/task_list_manager.go` NewManager resolves domain name once with GetDomainName and fails construction on error; newTaskListConfig captures that name, exact task-list name (including partition), and type in closures. The property values are live on each closure invocation, not frozen at construction.

* Append: `tasklist/task_writer.go` appendTask samples per attempt, derives WithTimeout from caller context, defers cancel, checks stopped, then selects enqueue versus deadline. Enqueue timeout returns ServiceBusy; after enqueue it selects buffered result, deadline (wrapped context error), or stop. An accepted write can complete after caller timeout/cancellation. Nonpositive duration gives an already expired context, but Go select can choose an immediately ready channel as well. Duration is signed nanoseconds (up to i64 bounds); Go context uses the earlier caller deadline. Native `matching_runtime_native.rs` writer_live_provider samples key/default/filter on demand, assembled by `with_writer_live`, bound in `matching_registry_native.rs` build_owner, and `matching_writer_native.rs` append_inner samples each retry. It clamps nonpositive to now; sender/response deadline paths preserve queue-full versus internal distinction and accepted writes remain alive. Rust future drop cancels caller wait; parent deadline depends on RPC future cancellation. Exact Go ready-channel versus already expired select fairness, status mapping on caller cancellation, and post-admission stop race require hosted behavioral comparison. Native checks stopped before sampling unlike Go. Tokio deadline arithmetic uses positive i64 nanoseconds (about 292 years); platform clock limits and `timeout_at` ready ordering need extreme-value verification.
* Local poll: `tasklist/matcher.go` pollNonBlocking samples each call; positive uses child context and deferred cancel to wait locally, bounded by parent; nonpositive does immediate nonblocking receive. Poll then attempts forwarding or continues local matching, and parent cancellation ends the poll. Native runtime duration_provider/with_local_poll_wait supplies signed ns, `forward_state` binds provider; dispatcher forwards after a live sampled wait, clamping negatives to zero and timer is dropped with the surrounding poll future. The existing `matching_rpc_local_poll_wait_delays_forwarding_and_reloads` exercises legacy RPC assembly, not proof of configured native path. Native query forwarding currently sleeps before forwarding in `forward_query_poll_inner`; verify whether it can still accept local queries during this sleep against Go. Exact zero ready selection and cancellation/forward race remain unverified.
* Local task: `matcher.go` Offer samples once after rate limit: positive child timeout first waits for local match, then cancels timer; zero/negative skip that stage, then immediate local match or forward; after local match with response channel it waits on original caller context. MustOffer samples once after rate limiting, creates a child timeout even when nonpositive, selects local match/parent cancel/child expiry, then retries local match and forwarding under parent context. Native `with_sync_wait` supplies the live provider to sync matcher and registry. Before this candidate native backlog reader incorrectly sampled localPollWaitTime for its initial local offer, and forwarded backlog acceptance at a nonroot partition also sampled the poll setting. This candidate changes both to localTaskWaitTime, retaining localPollWaitTime for polling. Root forwarded backlog uses a hardcoded 2s overall wait in native; verify its context against Go caller and forwarding timeout, including cancellation and success/error mapping. The focused provider test checks independent live values but does not exercise configured reader or RPC paths.

Conversion/binding: Go duration property accepts dynamic-client duration conversion, signed `time.Duration`; invalid conversion falls back to registered default. Native `cadence_persistence::dynamic_config::task_list_duration_bytes` selects context filters and uses signed nanoseconds via `cadence_common::duration::parse_nanos` for snapshot strings; invalid/overflow defaults, and runtime typed path uses i64. Positive values reach timers; waits clamp negative to zero where Go branches on >0 or creates an expired deadline. Fractional/unit parsing and runtime typed conversions must be compared on hosted Go oracle, including i64 min/max and out-of-range. Native providers currently call `cached_domain_name` on each sample, falling back to no domain filter on lookup failure, whereas Go binds a successfully resolved name at manager construction. Domain rename/cache eviction or lookup failure may therefore alter filter selection and permit construction where Go fails. Fixing binding consistently affects shared native assembly and is left as an explicit integration gap. Audit mixed RPC errors and cancellation, and timer lifecycle under stop, restart and recovery; source inspection is not evidence of operational parity.

This candidate does not modify the six quota conversion keys or other workers' ack/GC/idle and rawbyte provider/reader deadline changes.
