## Additional AdminService findings

### C10 — High — gRPC ResendReplicationTasks discards both requested event boundaries

- Rust `rust/crates/cadence-matching/src/grpc_admin.rs:1059` constructs start_event_id, start_version, end_event_id and end_version as None, ignoring the input's start_event/end_event.
- Go `go/common/types/mapper/proto/admin.go:686` maps all four components with ToEventID/ToEventVersion. Thrift Rust decoding already preserves ids 50/60/70/80 (`cadence-thrift/src/convert.rs:678`).
- Consequence: an operator requests replay of a particular event/version interval but Rust gRPC asks the remote cluster for an unbounded/default interval. The production resend implementation uses those fields to form the remote raw-history request (`cadence-service-core/src/admin_replication.rs:118`), so the loss reaches the real RPC.
- Fix: preserve presence and both components of each VersionHistoryItem. Not a C1–C9/Opus duplicate.

### C11 — High — Thrift queue task types are forwarded as protobuf numeric values

- Go's persistence task constants are Transfer=2, Timer=3, Replication=4, CrossCluster=6 (`go/common/constants/constants.go:203`). Admin protobuf values are respectively 1/2/3/4 (`go/idls/proto/uber/cadence/admin/v1/queue.proto:32`). Go explicitly translates (`go/common/types/mapper/proto/shared.go:991`, `:1008`).
- Rust Thrift RemoveTask/ResetQueue/DescribeQueue reads raw i32 values (`cadence-thrift/src/convert.rs:63`, `:701`, `:717`). Shared production handlers forward those values directly into History protobuf (`cadence-service-core/src/admin.rs:1980`, `:2031`, `:2082`).
- Consequence: Thrift RemoveTask with Transfer=2 reaches Go History as TIMER=2; it can remove a timer task instead of the intended transfer task. Timer=3 becomes replication; other queue operations similarly address the wrong queue or fail. Valid gRPC requests happen to survive because grpc_admin.rs:663/681/698 retains their original proto values; do not apply an unconditional numeric offset there.
- Fix: normalize at the transport boundary and use an explicit mapping (CrossCluster is not a uniform +1 offset). Handle INVALID as absent, as Go does. No prior duplicate.

### C12 — Medium — Thrift ReadDLQMessages drops replicationTasksInfo

- Go IDL `go/idls/thrift/replicator.thrift:191` declares field 40, a list of ReplicationTaskInfo. Go protobuf Admin mapper preserves it (`go/common/types/mapper/proto/admin.go:588`).
- Rust public model `cadence-api/src/admin.rs:833` has no such field. `cadence-service-core/src/admin_replication.rs:346` discards History's response.replication_tasks_info; Thrift writer `cadence-thrift/src/convert.rs:487` only emits fields 10/20/30.
- Consequence: Thrift DLQ inspection loses the identifying metadata for queued history tasks even when Go History supplies it. Direct gRPC Admin preserves the list (`cadence-matching/src/grpc_admin.rs:984`), so this is transport-dependent.
- Fix: add the list to the API model, copy it from History and encode/decode field 40, reusing the existing ReplicationTaskInfo codec. No prior duplicate.

### C13 — Medium — gRPC async-configuration getter relabels opaque queue blobs as JSON

- `cadence-matching/src/grpc_admin.rs:50` data_blob_out always writes encoding_type=2 regardless of the supplied DataBlob. async_config_out uses it for queue_config at 123; GetDomainAsyncWorkflowConfiguraton invokes that path at 526.
- Inbound async_config_in preserves encoding and the production update/get handlers retain the configuration (`cadence-service-core/src/admin.rs:2437`, `:2458`). Thus a supplied/stored ThriftRW blob (or unset encoding) changes encoding on a gRPC read while its bytes remain unchanged. Thrift's DataBlob codec preserves encoding (`cadence-thrift/src/convert.rs:241`).
- Go `go/common/types/mapper/proto/admin.go:1501` calls FromDataBlob, which preserves the encoding (`go/common/types/mapper/proto/api.go:756`).
- Consequence: update/read round trips return incompatible metadata for opaque queue configuration; a consumer can select the wrong decoder. Dynamic-config outputs are generated JSON and do not alone demonstrate this defect.
- Fix: map each actual encoding; use a JSON-specific constructor only for values known to have been JSON encoded. No prior duplicate.

### C14 — High — Admin gRPC isolation states are shifted despite identical wire enum values

- Both IDLs define INVALID=0, HEALTHY=1, DRAINED=2 (`go/idls/thrift/shared.thrift:2195`; `go/idls/proto/uber/cadence/api/v1/common.proto:147`). Rust API enum uses the same values (`cadence-api/src/enums.rs:304`). Go performs direct casts (`go/common/types/mapper/proto/admin.go:1455`, `:1477`).
- Rust Admin getters add 1 (`cadence-matching/src/grpc_admin.rs:417`, `:472`); setters subtract 1 (`:439`, `:498`). Both global and domain group methods are affected. Thrift codecs at `cadence-thrift/src/convert.rs:1101` correctly use raw values.
- Consequence: sending DRAINED=2 through gRPC stores Healthy=1; sending HEALTHY=1 stores Invalid=0. A Thrift-created Healthy group is reported as DRAINED over gRPC, and a Drained group becomes unknown proto value 3. Operators cannot reliably drain/re-enable groups across transports.
- Fix: map these enum values without offset and retain Go's invalid/unknown behavior. Related to C5's missing production isolation wiring, but a separate conversion defect that also affects configuration and mixed-transport administration.

### C15 — Medium — gRPC ReapplyEvents discards DataBlob encoding

- `cadence-matching/src/grpc_admin.rs:848` creates an events DataBlob with encoding_type=None and copies only data. Go `go/common/types/mapper/proto/admin.go:616` calls ToDataBlob, preserving encoding (`go/common/types/mapper/proto/api.go:766`). Thrift Rust preserves field 10 of DataBlob.
- This is independently visible at the adapter boundary. The current shared handler further ignores all encodings and attempts JSON with unwrap_or_default (`cadence-service-core/src/admin.rs:1210`), so unsupported/non-JSON events can become an empty successful reapply rather than the original events. Restoring only the gRPC field will not fix that underlying reapply behavior.
- Fix: preserve encoding and use the supported history-event blob decoder with error propagation. Separate from C13's outbound async-config relabeling; no prior C duplicate.

## Review limits / correction priorities

The highest-risk new findings are C10 (replication interval), C11 (wrong queue/task deletion through Thrift), and C14 (drain-state corruption through gRPC). Retain O10 as the existing C1, fix O30, and reject the proposed O15 int32-check change. O34 is already handled. For O11, first settle a single WorkflowExecutionInfo timestamp unit across internal adapters; a one-line formatter substitution is unsafe.

O31 and O32 illustrate why the production route matters: a helper defect is not sufficient evidence that the transport uses that helper. Conversely, the earlier C report's archival-registration observation only clears the Thrift route; gRPC still needs policy application. No runtime evidence or full parity certification is claimed here.
