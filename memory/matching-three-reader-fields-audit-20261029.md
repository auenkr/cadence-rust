- **GetTasksBatchSize: corrected, with allocation limit caveat.** `matching.getTasksBatchSize`, default 1000, domain name/task-list name/task type filters. Go binds manager domain name and list/type once, but reads the value once when creating all group buffers (capacity batch minus one) and again before every range persistence request; <=0 falls back to 1000 in both places. Native now samples once for all constructed buffers and once per range, retains positive i64 values for persistence rather than clamping at u32, and applies the same fallback. Buffer capacity uses usize and Tokio's channel maximum; extreme positive capacities can panic at a different threshold than Go's `make(chan, batch-1)` or fail allocation, so extreme allocation failure is not classified equivalent. Persistence backend limits/errors for enormous positive batches also remain backend-dependent. Dynamic changes do not resize existing buffers.
- **ReadRangeSize: corrected at scan boundary.** `matching.readRangeSize`, default 50000, unfiltered. Go samples on each of up to ten empty range scans, adds signed int64 with wraparound, caps only above max, sends bounds to persistence, and advances read level on empty results; zero makes no progress, negatives move backward, and very large values can wrap. Native previously converted negatives and values above u32 to zero and sampled once per turn; now samples each range and uses signed wrapping addition and the same upper cap. Persistence-specific handling of reversed or overflowed bounds and eventual cursor/ack consequences are not asserted identical by this static audit; those are pathological settings and require mixed-store validation. Fixed-value helper APIs remain u32, but the configured native consumer uses the signed live path.
- **AsyncTaskDispatchTimeout: corrected filter lifetime; extreme deadline caveat.** `matching.asyncTaskDispatchTimeout`, default 3s, domain/list/type filters. Go binds domain name at manager creation and samples on each eligible dispatch attempt; native previously looked up the domain name every attempt, and now captures it with the reader while sampling the overlay per attempt. Go only sets a deadline for an isolated group or rate > 1e-7 and an active/unknown domain; timeout is max(min(config, isolation duration when nonzero), duration(1s * number of buffers / rps) + 100ms), with Go conversion/wrapping behavior. Native dispatch uses `task_isolation::dispatch_timeout` and the same eligibility condition and signed inputs; zero/negative configured timeouts are subject to that minimum, and standby or tiny-rate default-group attempts have no deadline. Native uses saturating addition to an i64 nanosecond absolute clock for the deadline, so near-i64-max durations can expire earlier than Go's wider `time.Time`; extreme absolute deadline equivalence remains open. The provider is sampled even when the native eligibility check suppresses the deadline; this does not affect the computed deadline but differs in lookup timing. Domain lookup failure at construction can still differ from Go, whose manager creation fails when the domain cannot be resolved.
