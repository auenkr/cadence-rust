The new persistence trait is `cadence_persistence::matching_task_store::MatchingTaskStore`. It covers the operations called by `DurableTaskQueue` and is implemented by `SqliteTaskStore`. The concrete SQLite inherent methods remain available, preserving existing external callers and SQLite error variants. `DurableTaskQueue` stores `Arc<dyn MatchingTaskStore>`; existing `Arc<SqliteTaskStore>` call sites coerce at the queue constructor boundary. Matching writer and reader consume the queue interface and do not need direct storage types.

The trait deliberately preserves these contracts already implemented by SQLite and consumed by the queue:

- Lease returns a task-list record and uses the range fence; task-list updates are fenced by the acquired range.
- Batch creation receives source domains per task while fencing the target task list. Inserts and range verification remain one backend transaction.
- Reads return the ordered Go interval `(read_level, max_read_level]`, bounded by signed `batch_size`. Expired rows remain visible to the queue reader, which owns expiration behavior.
- Size counts task IDs strictly above the ack level; single deletion is not lease-fenced; bounded GC deletes IDs at or below the inclusive ack ID; task-list deletion checks the expected range.

The trait currently returns `matching_sqlite::Result` to preserve existing queue error behavior and avoid adding a speculative error variant before a driver adapter exists. Before implementing SQL drivers, normalize backend failures into a store-level error type while re-exporting legacy `matching_sqlite` names for compatibility. Do not collapse conditional lease errors into transient/database errors.

The runtime/registry constructor types remain SQLite-specific in this checkpoint by request from the runtime worker, who is freezing that candidate for production validation. This does not block the persistence abstraction: current queue construction accepts concrete SQLite `Arc` values through trait-object coercion. Generalizing runtime selection and registry ownership is the next coordinated integration slice before a MySQL/PostgreSQL adapter can be wired into production.


## MySQL v8 task-store adapter source slice (unvalidated)

Added `cadence_persistence::matching_mysql::MySqlTaskStore` implementing the persistence trait against existing Go MySQL v8 `task_lists` and `tasks` tables. It does not create or migrate schema. Backend error types now live in `matching_task_store`; `matching_sqlite::StorageError` and `Result` remain public re-exports with the prior SQLite variants and message strings. The shared error adds normalized `BackendErrorKind::{Timeout,Throttled,Internal,Permanent}`; Go MySQL timeout/throttling codes map to their category, and all Go-converted DB driver errors remain retryable. Conditional range errors remain separate and nonretryable. Persistence retry rules now use that classification. The Matching server writer still has SQLite-specific retry matching and requires a later coordinated update before MySQL is wired into runtime.

The adapter implements task-list read/lease/update, atomic task insert plus row lock/range fence, ordered bounded reads, count above ack, unfenced single delete, bounded ack delete, and range-checked task-list delete. It preserves Go's select-then-insert behavior for missing queues, including a duplicate insert error and range-zero row left behind when a positive previous range mismatches. It verifies existing primary keys and never mutates schema. Go DB routing is FarmHash32 over canonical UUID text + underscore + task-list name; the result is stored in `task_lists.shard_id` and selects the SQL database, while Go's `tasks` table has no shard-id column.

A synchronous custom connection pool mirrors Go's nonpositive-unlimited `maxConns`, `maxIdleConns` default 2 (clamped to max open), and max connection lifetime. Lifetime is checked when recycling/checking out, so it cannot interrupt an active operation. MySQL `useMultipleDatabases` is explicitly rejected by this single-database adapter; a sharded connection selector is separate work. TLS support maps Go MySQL plugin's `tls-custom`, one `caFile`, paired client cert/key, host verification and relevant connect options. It rejects unsupported connect attributes and unsupported `preferred` fallback semantics. Go MySQL plugin ignores `TLS.ServerName`, `CaFiles`, and `RequireClientAuth` on this outbound client path; those fields are therefore not applied. Its forced `parseTime` has no impact on task blobs; forced `clientFoundRows` is enabled; forced `multiStatements` is not needed by the adapter's single-statement CRUD.

Dependency audit: the only added runtime dependencies in the manifest are `mysql = 26.0.1` with `default-features = false`, `minimal-rust`, and `rustls-tls-ring`, plus direct `farmhash = 1.1.5` (already present transitively in the lockfile via cadence-common). Crates.io reports mysql 26.0.1 non-yanked and edition 2021; rustls 0.23's declared MSRV is 1.71, below the installed rustc 1.99. The crate publishes no own rust-version. Source was downloaded and inspected for sync `Conn`, `OptsBuilder`, `SslOpts`, error, and capability APIs. No Cargo.lock resolution/update/build/test ran; the heavy lane must resolve the new MySQL dependency graph before any `--locked` command.

`tests/fixtures/matching-mysql-task-store-oracle.json` records source-derived Go operation expectations. New source tests check exact Go v8 table primary keys, FarmHash32's published vector, normalized driver categories, and fail-closed connect attributes. These tests have not been run. The fixture is source-derived, not observed Go/MySQL test evidence. No SQL adapter is wired into server runtime yet. Remaining config limitations include Go duration strings beyond one unit, arbitrary MySQL connect attributes, multiple configured databases, and Rustls/system-root behavior differences; unsupported input fails explicitly where detected.

## MySQL domain metadata source slice (unvalidated)

Added `matching_domain_mysql::MySqlDomainMetadataStore` as a read-only source for Matching's cache. It takes the same `MySqlTaskStoreConfig` used by the MySQL task store and now shares its synchronous connection pool construction/options, including TLS and configured pool limits. It reads `domain_metadata.notification_version`, exact name/UUID lookups, and `domains` pages from Go's default shard 54321. UUIDs remain 16-byte binary keys; page ordering/token behavior follows Go's raw UUID `id > token ORDER BY id LIMIT page_size`, returning a last-row token for every full page. A shared decoder now makes SQLite and MySQL paths use the same Go DomainInfo ThriftRW/Snappy parsing and nested blob/config semantics. No domain writes/schema migration were added.

This is only the persistence source. Runtime selection, default-store/cache construction, source switching, and mixed-cluster behavior remain unimplemented and must be coordinated with the runtime/cache worker. No build/test or lockfile change was made. The MySQL reader currently has no per-call three-second cancellation equivalent to Go's context; configured connect/read/write timeouts apply, but this remains a parity gap to resolve before production wiring. No observed MySQL oracle evidence exists yet.
