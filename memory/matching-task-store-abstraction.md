The new persistence trait is `cadence_persistence::matching_task_store::MatchingTaskStore`. It covers the operations called by `DurableTaskQueue` and is implemented by `SqliteTaskStore`. The concrete SQLite inherent methods remain available, preserving existing external callers and SQLite error variants. `DurableTaskQueue` stores `Arc<dyn MatchingTaskStore>`; existing `Arc<SqliteTaskStore>` call sites coerce at the queue constructor boundary. Matching writer and reader consume the queue interface and do not need direct storage types.

The trait deliberately preserves these contracts already implemented by SQLite and consumed by the queue:

- Lease returns a task-list record and uses the range fence; task-list updates are fenced by the acquired range.
- Batch creation receives source domains per task while fencing the target task list. Inserts and range verification remain one backend transaction.
- Reads return the ordered Go interval `(read_level, max_read_level]`, bounded by signed `batch_size`. Expired rows remain visible to the queue reader, which owns expiration behavior.
- Size counts task IDs strictly above the ack level; single deletion is not lease-fenced; bounded GC deletes IDs at or below the inclusive ack ID; task-list deletion checks the expected range.

The trait currently returns `matching_sqlite::Result` to preserve existing queue error behavior and avoid adding a speculative error variant before a driver adapter exists. Before implementing SQL drivers, normalize backend failures into a store-level error type while re-exporting legacy `matching_sqlite` names for compatibility. Do not collapse conditional lease errors into transient/database errors.

The runtime/registry constructor types remain SQLite-specific in this checkpoint by request from the runtime worker, who is freezing that candidate for production validation. This does not block the persistence abstraction: current queue construction accepts concrete SQLite `Arc` values through trait-object coercion. Generalizing runtime selection and registry ownership is the next coordinated integration slice before a MySQL/PostgreSQL adapter can be wired into production.


## MySQL v8 task-store adapter source slice (unvalidated)

Added `cadence_persistence::matching_mysql::MySqlTaskStore` implementing the persistence trait against existing Go MySQL v8 `task_lists` and `tasks` tables. It does not create or migrate schema. Backend error types now live in `matching_task_store`; `matching_sqlite::StorageError` and `Result` remain public re-exports with the prior SQLite variants and message strings. The shared error adds normalized `BackendErrorKind::{Timeout,Throttled,Internal,Permanent}`; Go MySQL timeout/throttling codes map to their category, and all Go-converted DB driver errors remain retryable. Conditional range errors remain separate and nonretryable. Persistence retry rules now use that classification. The Matching server writer still has SQLite-specific retry matching and requires a later coordinated update before MySQL is wired into runtime.

The adapter implements task-list read/lease/update, atomic task insert plus row lock/range fence, ordered bounded reads, count above ack, unfenced single delete, bounded ack delete, and range-checked task-list delete. It preserves Go's select-then-insert behavior for missing queues, including a duplicate insert error and range-zero row left behind when a positive previous range mismatches. It verifies existing primary keys and never mutates schema. Go DB routing is FarmHash32 over canonical UUID text + underscore + task-list name; the result is stored in `task_lists.shard_id` and selects the SQL database, while Go's `tasks` table has no shard-id column.

A synchronous custom connection pool mirrors Go's nonpositive-unlimited `maxConns`, `maxIdleConns` default 2 (clamped to max open), and max connection lifetime. Lifetime is checked when recycling/checking out, so it cannot interrupt an active operation. MySQL `useMultipleDatabases` is explicitly rejected by this single-database adapter; a sharded connection selector is separate work. TLS support maps Go MySQL plugin's `tls-custom`, one `caFile`, paired client cert/key, host verification and relevant connect options. It rejects unsupported connect attributes and unsupported `preferred` fallback semantics. Go MySQL plugin ignores `TLS.ServerName`, `CaFiles`, and `RequireClientAuth` on this outbound client path; those fields are therefore not applied. Its forced `parseTime` has no impact on task blobs; forced `clientFoundRows` is enabled; forced `multiStatements` is not needed by the adapter's single-statement CRUD.

Dependency audit: the only added runtime dependencies in the manifest are `mysql = 26.0.1` with `default-features = false`, `minimal-rust`, and `rustls-tls-ring`, plus direct `farmhash = 1.1.5` (already present transitively in the lockfile via cadence-common). Crates.io reports mysql 26.0.1 non-yanked and edition 2021; rustls 0.23's declared MSRV is 1.71, below the installed rustc 1.99. The crate publishes no own rust-version. Source was downloaded and inspected for sync `Conn`, `OptsBuilder`, `SslOpts`, error, and capability APIs. A source review found `ClientIdentity::new` requires `Into<Cow<'static, Path>>`, so the adapter now passes owned `PathBuf`s. Go's driver defaults host-only TCP addresses to port 3306; Rust now handles DNS names and bracketed/unbracketed IPv6 literals with that default. The Go-style timeout parser accepts signed/composite forms and ns/µs/Greek-μs units and checks Go's signed nanosecond range. Negative connect timeout maps to Go's no-timeout behavior; negative read/write timeout maps to a one-nanosecond socket deadline because mysql 26 exposes only relative unsigned socket timeouts. Rust source tests and Go `time.ParseDuration` oracle cases cover composite values, signs, Unicode micro units, sub-nanosecond truncation and the int64 overflow boundary. No Cargo.lock resolution/update/build/test ran; the heavy lane must resolve the new MySQL dependency graph before any `--locked` command.

`tests/fixtures/matching-mysql-task-store-oracle.json` records source-derived Go operation expectations. New source tests check exact Go v8 table primary keys, FarmHash32's published vector, normalized driver categories, fail-closed connect attributes, default-port parsing, and Go duration boundaries. These tests have not been run. The fixture is source-derived, not observed Go/MySQL test evidence. No SQL adapter is wired into server runtime yet. Remaining config limitations include arbitrary MySQL connect attributes, multiple configured databases, and Rustls/system-root behavior differences; unsupported input fails explicitly where detected.

Idle checkout no longer sends a MySQL `PING`: mysql 26 has no equivalent public local-validity method, and Go's `database/sql` validator only checks local closed/busy state. The Rust pool now reuses idle sockets without a network probe and marks a lease for discard on mysql 26 connectivity errors (`IoError`, driver, codec, or TLS). Transaction leases are poisoned before transaction start and only cleared after successful commit, because mysql 26's implicit rollback in `Transaction::drop` hides rollback failures; early-return transactions are safely discarded after Drop has attempted rollback. This matches Go's stale-idle failure timing and prevents a known broken connection from cycling back into the pool. `maxConnLifetime` uses connection-creation timestamps, expires idle connections at checkout and connections at return, and never interrupts an active operation.

The Go call-site audit found Matching tasklist persistence methods in `go/service/matching/tasklist/db.go` pass `context.Background()` for lease, update, create, task reads, ack deletes, size, and task-list reads; SQL store methods forward those contexts and do not add an operation deadline. Task writer `AppendTaskTimeout` is not propagated because taskListDB substitutes Background. Therefore the Rust task-store trait does not invent a task timeout. Domain cache persistence is different: `common/cache/domainCache.go` sets an outer `domainCachePersistenceTimeout = 3s` around GetMetadata and the whole page refresh; each page gets a child timeout bounded by that same outer deadline. GetDomain cache misses get their own 3s timeout.

MySQL domain reads use a dedicated non-pooled `mysql_async::Conn` per read. The persistence API remains synchronous, so a Tokio multi-thread runtime owned by the shared MySQL pool executes the async operation; the caller waits on a channel only until its monotonic deadline, then aborts the task. An RAII pool-slot guard lives in the spawned future and releases on normal completion or task cancellation. Successful/error query completion explicitly awaits `Conn::disconnect`; timed-out connections are never returned to either pool. No control connection or `KILL QUERY` is used, so timeout cancellation does not add an unaccounted connection or risk a delayed kill against a reused connection ID. The domain cache methods retain timeout-bearing APIs; Go's cache applies one outer 3s deadline to metadata plus the full refresh, each list-page context being bounded by that outer deadline; a cache-miss GetDomain gets its own 3s deadline.

The async driver is pinned exactly to published `mysql_async = 0.37.1`; crates.io's sparse index reports it non-yanked, while 0.37.0 is yanked. The 0.37.1 manifest does not declare an MSRV; upstream CI tests stable. Enabled features are `minimal-rust`, `rustls-tls`, and `ring`, matching this workspace's minimal Rustls/ring posture. Its Tokio dependency enables `io-util`, `fs`, `net`, `time`, `rt`, and `sync`; cadence-persistence additionally enables Tokio `rt-multi-thread` for its dedicated runtime. `Conn::routine` sets its internal `disconnected` flag while awaiting protocol I/O (`src/conn/mod.rs`); on cancellation at that Pending point, `Conn::drop` skips its async drain/QUIT path and dropping the connection drops the stream. This is why query cancellation should close the active server socket rather than drain a pending result. Production closures must await the MySQL protocol operation directly and must not add external awaits while retaining a connection with pending results. This source-level cancellation argument is not runtime proof.

`mysql_async` is locally patched in `rust/vendor/mysql_async-0.37.1` to support the Matching domain-read DSN socket timeouts. TCP `timeout` bounds only connect; read and write durations begin independently on each socket operation and survive Pending polls. Go's TLS handshake inherits the absolute read deadline from greeting receipt and write deadline from the SSLRequest, without refreshing either at handshake start. The vendor patch carries those absolute deadlines through raw TLS handshake I/O, then disables the inherited deadlines so regular TLS I/O resumes fresh per-operation deadlines. Archive provenance, checksum, and retained licenses are recorded in `rust/vendor/mysql_async-0.37.1/CADENCE-PATCH.md`. TLS behavior has source tests but remains uncompiled and unrun under the runtime/build gate.

Ignored DB test source now covers SLEEP cancellation while another transaction is active, SLEEP cancellation with `max_conns=1` followed by a successful query, slow multi-row result draining, fast connect failure and slot release, and successful query completion/disconnect. These tests are not run. Required DB validation remains: run every ignored test against MySQL 8, verify maxConns=1/2 server connections, ensure worker/slot/server-thread cleanup after cancellation, and verify the unrelated transaction remains usable. ## MySQL domain metadata source slice (unvalidated)

Added `matching_domain_mysql::MySqlDomainMetadataStore` as a read-only source for Matching's cache.
