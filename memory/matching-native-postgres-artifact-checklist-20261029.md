## Required compatibility and scenario evidence

- **Existing SDK and mixed topology:** verify the Go SDK probe actually ran and completed its workflow (not merely process startup); inspect `probe.log`, SDK-specific logs under `out/gate/run/`, plus `results.json`. Confirm Go Frontend, History, Worker are running and Rust Matching is the only Matching service. `results.json` records `goMatchingStarted: false`; check the recorded `goServices`, `rustServices`, `topology`, service logs, and Rust launch command agree. Check shared PostgreSQL configuration on both sides, with Go schema initialization and no parallel Go Matching.
- **Shared Go PostgreSQL schema:** inspect the sanitized Go/Rust service configs and PG URL/database settings in `out/gate/run/`. The harness's `goSchemaOnly` / `db-observations.json` check in `tests/run-go-service-baseline.py` is only wired for `args.mysql` (the code calls `check_go_schema_only()` only inside `if args.mysql`). Therefore a missing PG `goSchemaOnly` or PG `db-observations.json` is expected, not proof of schema compatibility. Establish the shared Go-owned schema from config/startup evidence and the scenario queries against the PG tables; do not claim the MySQL schema-only assertion ran.
- **Restart, crash recovery, idle recovery:** common arguments request process restart, two-instance failure recovery, and idle check 3 seconds. Require explicit probe outcomes and the restart/recovery SDK logs/checkpoints where emitted; correlate with `rust-server-*.log` and the final JSON record in `probe.log` (`processRestart`, `idleUnloadAndRecovery`, `gracefulDrainRecovery`, `probeScenarios`). These fields are emitted by the Node probe, not copied into harness `results.json`. A `result: passed` summary alone is weaker than the scenario records. Confirm recovered SDK workflows complete once, and failed Rust Matching is absent while the surviving Rust node takes work.
- **PostgreSQL GC-domain:** inspect `postgresGcDomain.json` and `probeScenarios.postgresGcDomain`: expect `result: "passed"`, `taskGarbageCollection` and `domainMetadata`. The assertion checks acked task removal, survival of an unacknowledged control task, persisted ack/range consistency and Go domain metadata on PostgreSQL. The harness enables it through `CADENCE_PROBE_PG_GC_DOMAIN`; flag presence alone is not evidence.
- **Query standby:** inspect `queryStandbyForwarding.json` and `probeScenarios.queryStandbyForwarding`: expect `result: "passed"`, `directChildAnswered: true`, and `frontendAnswered: 6`. The probe has the only poller on the parent partition while queries target the child directly and through Go Frontend.
- **List partitions:** inspect `listTaskListPartitions.json` and `probeScenarios.listTaskListPartitions`: require the returned `results` for each source/list/type to match expected keys/order and ring-member owners. It checks every Rust node plus Go Frontend and expects three write partitions. This flag also changes dynamic config; actual response evidence is required.
- **Durable restart:** inspect `durableRestartDrain.json` and `probeScenarios.durableRestartDrain`: expect `result: "passed"`, three `queuedBeforeRestart` partition records with persisted rows, a restart record, and three unique `drainedAfterRestart` activities. This explicitly checks multi-partition backlog survival across Rust Matching restart.
- **Auto-config hint:** inspect `autoConfigHint.json` and `probeScenarios.autoConfigHint`: require `decisionHint.enableAutoConfig: false` and `activityHint.enableAutoConfig: false`. The helper asserts the hint message exists (not just a false protobuf default) for both polls. The harness overrides `matching.enableClientAutoConfig=false`; verify config and JSON together.

## Review limits and proven collector behavior

- `tests/matching_evidence.py` is a selected durable-copy helper used when `--evidence-dir` is supplied; the workflow artifact is the full `out/` upload described above. Its `copy_evidence()` copies a fixed list (`probe.log`, `results.json`, `run.exit`, `command.txt`, selected SDK logs, DB observations and service logs) and selected files under `rust-matching/`, then creates `source.json`, `binaries.json`, `config-hashes.json`, `results-copy.json`, and `EVIDENCE.md`. It does not promise a recursive copy of every probe artifact. Review the workflow's full nested tree for this lane.
- The `goSchemaOnly` assertion is demonstrably MySQL-only in `run-go-service-baseline.py`; do not treat its absence in PG results as a collector defect or report it as a PG pass. No PG-specific compact DB observation is produced by that MySQL-only path.
- Do not infer any scenario passed from arguments, a top-level green Actions conclusion, or `acceptanceEligible` metadata. Require matching SHA identity, all nested exits, transcript assertions, topology, and container cleanup together.
- This lane is bounded PostgreSQL acceptance evidence for Matching. It does not complete the Matching parity audit by itself and does not establish another service's completion.
