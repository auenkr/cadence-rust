## Implemented

Added `rust/crates/cadence-history/src/mutable_state.rs` with the following
initial foundation:

- Mutable state maps for activity, timer, child workflow, request cancellation,
  signal, and signal-request records, including pending/update/delete tracking.
- Execution info, buffered events, version histories, history event sequence,
  database next-event condition, and optional checksum state.
- Local event allocation and contiguous replicated-event ID validation using
  the generated Cadence `HistoryEvent` type.
- Activity and timer upsert/delete transitions.
- Mutation and snapshot output structures mirroring the corresponding Go
  persistence buckets, and snapshot rejection for buffered events or multiple
  transient batches.
- Rust tests for contiguous local/replicated event IDs, update/delete output,
  snapshot population, and snapshot validation.

## Gaps remaining

This does not complete H3a or establish history parity. Specifically:

- The state uses `serde_json::Value` for execution info and persistence info
  records. Rust equivalents of Go persistence `WorkflowExecutionInfo`,
  `ActivityInfo`, `TimerInfo`, `ChildExecutionInfo`, `RequestCancelInfo`, and
  `SignalInfo` are still needed. The local mutation/snapshot structures are
  provisional minimal definitions; they are not yet the persistence crate's
  durable workflow mutation/snapshot contract.
- Missing Go persistence buckets/fields include semaphore records, task
  categories and task inserts, workflow requests, activity/timer rewrite
  records, and transaction checksum semantics.
- Missing close transaction behavior: prepare/validate policy, buffered-event
  limit and flush logic, reset handling, event batching/replication tasks,
  last-first/last-write event bookkeeping, update timestamps, database state
  bookkeeping, checksum generation, and transaction cleanup.
- Missing all individual Go `Add*Event` and `Replicate*Event` transitions in
  `mutable_state_builder*.go` (workflow start/completion/failure/timeout,
  decision, activity, timer, child workflow, cancellation, signal, semaphore,
  search attributes, marker, terminate, and continue-as-new), along with their
  validation, task generation, cache updates, and side effects.
- Go `mutable_state_builder*_test.go` cases have not been ported; the Rust tests
  added here cover only the foundation above.

The next H3a work should first add typed persistence contracts and transaction
policy semantics, then port event transition groups and their Go test cases.
