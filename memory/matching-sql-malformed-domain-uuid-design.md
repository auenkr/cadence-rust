# Matching: SQL malformed DomainUUID parity — Rust pointers, parser diff, minimal design (source-only)
Builds on `memory/matching-nil-query-domain-source-review.md` (14ccc39b6). No code, no CI, **all tests unrun**. Paths: Rust under `rust/crates/`, Go under `go/`.

## Verified Go facts
- google/uuid v1.6.0 `Parse` (module cache uuid.go:66-120), by length: **36** hyphen form; **45** needs `strings.EqualFold(s[:9],"urn:uuid:")` else `invalid urn prefix: "<9 chars>"`; **38** just drops `s[1:]` — first and last chars are NOT checked (any bracket/char accepted; last byte ignored); **32** raw hex; other length => `invalid UUID length: N`. Bad hyphen position or non-hex => `invalid UUID format` (for 32: also `invalid UUID format`). `MustParse` panics with string `"uuid: Parse(<s>): <err>"`.
- Cassandra (settled): gocql `marshalUUID` string case (gocql@b225f9b53fa1 marshal.go:1784) calls `ParseUUID` (uuid.go:64): lenient (hyphens skipped at even positions, hex either case, needs exactly 32 hex digits) and returns `fmt.Errorf("invalid UUID %q", input)`. **Error return, not panic.** Flow: nosqlplugin/cassandra/domain.go:249-252 `Query(templateGetDomainQuery, domainID).Scan(&domainName)` returns err -> handler domainName swallows -> "" -> request continues. Consequence: a Cassandra-valid-but-differently-formatted ID (uppercase, hyphens elsewhere) would be FOUND by gocql in Go; exact-string Rust lookup would not (low priority, noted).
- So the panic is SQL-only (sqlite/mysql/postgres all go through sql_domain_store.go:206-207 MustParseUUID).

## Rust today (key finding: the handler does NOT use the Go-shaped lookup)
- Handler domain resolution is `Matching::domain_name` (`cadence-matching/src/grpc_matching.rs:1711`) -> `History::domain_name` (`grpc_internal.rs:12`): `uuid::Uuid::parse_str(id)` failure => `Status::invalid_argument("Domain UUID is not valid.")`, then in-memory `state.domains.describe`; errors propagate with `?` (not swallowed). Used at e.g. grpc_matching.rs:1778/2017 (polls, AFTER quota+deadline+payload check), 2237, 2461, ... Differs from Go on all backends: Go swallows errors, runs it FIRST (before quota), and panics only for SQL.
- Quota path swallows: `check_rpc_quota` (1717-1726) `self.domain_name(id).unwrap_or_default()`. Metrics wrapper: `self.metrics.matching_request(..., self.metric_domain_name(id) ...)` (`cadence-service-core/src/matching_metrics.rs` `fn matching_request`; `metric_domain_name` at grpc_matching.rs:443 uses `domain_name_resolver` set by `with_domain_cache` :436 -> `MatchingDomainCache::cached_domain_name` (matching_domain_cache.rs:723), non-blocking, no persistence, falls back to `domain_name_for` :17 on the in-memory store).
- `MatchingDomainCache` (matching_domain_cache.rs:429; `get_domain_by_id` :697, `get_domain_name` :716) is the Go-shaped cache; built in `launcher.rs:1260-1290` from `stores.domain_metadata_source`, but only feeds metrics + persistence limiter (`with_domain_cache` limiter.rs:210), NOT the RPC handlers. Source impls: `DomainMetadataSource` trait (:81); Cassandra :205, MySQL :248, shared sqlite/postgres :164; `metadata_source_error` maps `InvalidUuid` -> BadRequest (:126) (persistence matching_domain_metadata.rs:332/646, mysql.rs:108, postgres.rs:102 return InvalidUuid via Rust `Uuid::parse_str` — again not Go semantics).
- Wrapper: every handler body is inside `crate::matching_panic::capture(...)` (`matching_panic.rs:17`); `panic_message` (:59) already produces `panic object is not error: "<msg>"` with `{:?}` of the string payload, `is_captured_panic` (:48) maps to Unknown/Thrift 0x05. So a Rust `panic!("uuid: Parse(abc): invalid UUID length: 3")` inside the capture closure already yields the exact captured text. (Verify `{:?}` escaping equals Go `%#v` for quotes/non-ASCII; Go %#v escapes via strconv.Quote; Rust Debug escapes differently for some unicode — test with ASCII only plus one escape case.)
- Distinguishing SQL without a global check: `ConfiguredMatchingStores` (`matching_task_store.rs:23`) is built per backend at :162 (Cassandra, `domain_metadata_source` Some), :182 (sqlite, `None`!), :238 (mysql), :292 (postgres). Note sqlite has no domain_metadata_source, so the backend tag cannot be inferred from it.

## Smallest design
1. New enum in `matching_task_store.rs`: `DomainIdParse { GoogleUuidPanic /*sqlite,mysql,postgres*/, Lenient /*cassandra*/ }`; add field `domain_id_parse` to `ConfiguredMatchingStores`, set at the four constructors (:162 Lenient, :182/:238/:292 GoogleUuidPanic). Default in tests/embedded: Lenient (embedded-development is not Go-config parity).
2. New pure fn `go_uuid_parse_error(s:&str)->Option<String>` (new small module or in grpc_matching.rs) re-implementing v1.6 Parse exactly as above (length switch 36/45/38/32; EqualFold urn prefix; `{:?}`-style quoting for the `%q` urn message). Unit-table test with Go-derived expectations: lengths 0/3/31/33/35/37/39/44/46, 32 valid/invalid hex, 36 bad hyphen, 38 with arbitrary bracket chars (accepted), 45 `URN:UUID:` (accepted), 45 `urn:xxxx:` (prefix error).
3. `Matching` gets `domain_id_parse: DomainIdParse` (builder `with_domain_id_parse`, wired next to `with_domain_cache` in launcher from `configured_matching_stores`). New first step `fn go_domain_name(&self, id)` in every handler where Go calls `h.domainName` first: if mode==GoogleUuidPanic && !id.is_empty() && let Some(e)=go_uuid_parse_error(id) => `panic!("uuid: Parse({id}): {e}")` (caught by existing `capture`). Else resolve and **swallow** errors to "" (replacing the current `?` semantic only where Go swallows; the existing Rust InvalidArgument for malformed IDs under Lenient/embedded must be re-examined: Go returns no error there, so that is a separate parity gap).
4. Ordering per handler: capture -> go_domain_name (panic) -> quota -> deadline BadRequest -> payload/nil checks. Today Rust runs metrics wrapper (`metric_domain_name` is non-panicking, fine) then quota, so insert the call before `check_rpc_quota` (e.g. grpc_matching.rs:1765, 2004 and each sibling).
