# Matching: SQL malformed DomainUUID parity — Rust pointers, parser diff, minimal design (source-only)
Builds on `memory/matching-nil-query-domain-source-review.md` (14ccc39b6). No code, no CI, **all tests unrun**. Paths: Rust under `rust/crates/`, Go under `go/`.

## Verified Go facts
- google/uuid v1.6.0 `Parse` (module cache uuid.go:66-120), by length: **36** hyphen form; **45** needs `strings.EqualFold(s[:9],"urn:uuid:")` else `invalid urn prefix: "<9 chars>"`; **38** just drops `s[1:]` — first and last chars are NOT checked (any bracket/char accepted; last byte ignored); **32** raw hex; other length => `invalid UUID length: N`. Bad hyphen position or non-hex => `invalid UUID format` (for 32: also `invalid UUID format`). `MustParse` panics with string `"uuid: Parse(<s>): <err>"`.
- Cassandra (settled): gocql `marshalUUID` string case (gocql@b225f9b53fa1 marshal.go:1784) calls `ParseUUID` (uuid.go:64): lenient (hyphens skipped at even positions, hex either case, needs exactly 32 hex digits) and returns `fmt.Errorf("invalid UUID %q", input)`. **Error return, not panic.** Flow: nosqlplugin/cassandra/domain.go:249-252 `Query(templateGetDomainQuery, domainID).Scan(&domainName)` returns err -> handler domainName swallows -> "" -> request continues. Consequence: a Cassandra-valid-but-differently-formatted ID (uppercase, hyphens elsewhere) would be FOUND by gocql in Go; exact-string Rust lookup would not (low priority, noted).
- So the panic is SQL-only (sqlite/mysql/postgres all go through sql_domain_store.go:206-207 MustParseUUID).

Unit-table test with Go-derived expectations: lengths 0/3/31/33/35/37/39/44/46, 32 valid/invalid hex, 36 bad hyphen, 38 with arbitrary bracket chars (accepted), 45 `URN:UUID:` (accepted), 45 `urn:xxxx:` (prefix error).

New first step `fn go_domain_name(&self, id)` in every handler where Go calls `h.domainName` first: if mode==GoogleUuidPanic && !id.is_empty() && let Some(e)=go_uuid_parse_error(id) => `panic!("uuid: Parse({id}): {e}")` (caught by existing `capture`). ## Current-master reassessment (2026-10-26, HEAD 9dbbab68d)
This old Cassandra formatting caveat is **not an RPC behavior gap in the current Matching request path**. The source trace separates three behaviors:

- The Go handler's `h.domainName` call is a metrics lookup (`go/service/matching/handler/handler.go:559`). It invokes the Cassandra domain store, whose gocql UUID string binder calls the pinned gocql `ParseUUID` at `go/pkg/mod/github.com/gocql/gocql@v0.0.0-20211015133455-b225f9b53fa1/{marshal.go:1784,uuid.go:64}`. That parser accepts uppercase hex and skips hyphens at even hex offsets, requires 32 hex digits, and returns an error (not a panic) for invalid input. The handler swallows lookup errors and continues.
- Rust's handler metrics resolver is `Matching::metric_domain_name` (`rust/crates/cadence-matching/src/grpc_matching.rs:483`), wired by `with_domain_cache` (`:461-467`) to `MatchingDomainCache::cached_domain_name` (`matching_domain_cache.rs:738`). It reads the snapshot by the original string key and does no persistence I/O. Thus an alternate spelling can omit the domain metric tag. `DomainIdParse::Lenient` on Cassandra (`matching_task_store.rs:158`, carried by `launcher.rs:1267`) keeps the Go behavior that malformed metrics lookup input does not panic.
- Actual Rust domain validation is separate: `Matching::domain_name` (`grpc_matching.rs:1746-1759`) delegates to `History::domain_name` (`grpc_internal.rs:12-27`), which uses `uuid::Uuid::parse_str` and the in-memory domain manager. The Cassandra metadata cache's real cache-miss source also parses with `Uuid::parse_str` (`cadence-persistence/src/matching_domain_metadata.rs:331-341`) before binding typed UUID bytes. This strict validation path does not inherit the metrics lookup's swallowed-error semantics.

## Correction: Matching Cassandra cache normalization (2026-10-26)
The conclusion above is incorrect. Independent review 18033252 correctly points out that this telemetry label is also the Matching quota context: `MatchingPersistenceLimiter::record_task_rejection` resolves a domain ID through `cached_domain_name`, then supplies the returned domain name to the rejection metric. On Cassandra, Rust previously looked up the UUID's exact string spelling while Go's `h.domainName -> GetDomainName -> Cassandra SelectDomain` sends the spelling through the pinned gocql parser and resolves the domain name. Uppercase or gocql-valid nonstandard hyphen placement therefore lost the quota metric domain context in Rust. This is a concrete backend parity gap even though it does not change RPC acceptance.

The fix is Cassandra-specific at the `DomainMetadataSource` normalization hook. It mirrors pinned gocql's parser (32 ASCII hex digits, hyphens only at even digit offsets, uppercase accepted), canonicalizes page IDs before snapshot insertion, and canonicalizes cache/read-through lookup IDs. Invalid UUIDs yield no value from the cache-only `cached_domain_name`, preserving Go's swallowed lookup error in quota/metric context. SQL sources retain identity normalization and their existing UUID parser/order, and no RPC validation or History behavior changes. Regression coverage checks gocql accepted/rejected spellings and resolves an uppercase cached Cassandra ID through an unhyphenated lookup.
