## Top 5 PORTABLE items (by value)

1. **Rate-limit matrix (row 15, TestRatelimitBehavior, 17 subcases)** → `matching_limiter.rs` with LIMITER-SEAM. Pure function over the limiter; no production change. Highest value because it pins the cancel/return-token semantics.
2. **Query-forward family (rows 12, 13, 29, 30)** → RPC tests with a new FAKE-PARENT implementing `query_workflow` (recording, busy, failing variants). Pins the wire fields (`task_list.name`, `kind`, `forwarded_from`), the no-rate-limit rule, busy → local fallback, and parent-error propagation.
3. **MustOffer timeout and forward-error family (rows 23, 24, 27)** → READER-SEAM tests in `matching_reader.rs`: no ack on timeout, one forward per token, and token release on expiry after a forward error. Go's error return becomes "keep the row, retry", which is the Rust behaviour to pin.
4. **Forwarded poll failure fallback (row 39, Test_pollOrForward_ForwardTaskThenPoll; plus row 14 ForwardPollError)** → RPC test with a failing `poll_for_decision_task` parent; asserts a local add delivered while parked, and no parent call for root or sticky polls.
5. **AutoConfigHint on poll responses (row 41)** → mixed-gate probe in `tests/matching-service-compat.cjs` (decision poll near the query probe, ~1188-1190), asserting `enableAutoConfig === false` through the Go frontend, plus one RPC unit test. This is the only SDK-visible field in this set, and it corrects a false claim in the map.

## Parity gaps and items to verify (not test-only)

- **Panic recovery missing in Rust (rows 5, 6; also the handler level).** Go `handler/handler.go` wraps every matching RPC in `log.CapturePanic(recover(), ...)`, and `membership.go` recovers the membership loop and per-manager stop. Rust has no equivalent in production (`catch_unwind` appears only in test code). A panic in a Rust matching RPC or membership task is not converted to an error. Needs an issue; a fix changes program logic, so it is out of scope for this review.
- **Sticky query forwarding (row 11, to verify).** Go `matcher.go:804` only short-circuits when `fwdr == nil`. For a sticky list the forwarder exists, so `OfferQuery` reaches `ForwardQueryTask` and returns `ErrTaskListKind` (forwarder.go:182). Rust `grpc_matching.rs:2651` skips forwarding for `kind == 2` and waits locally. The external outcome may be identical because `check_sticky_poller` (`grpc_matching.rs:2580`) rejects a sticky query with no recent poller first, but this needs a probe to confirm.
- **`domainName` swallow (row 4, to verify).** Rust `History::domain_name` (`grpc_internal.rs:12`) returns `Err` (InvalidArgument / NotFound), and `check_rpc_quota` swallows via `unwrap_or_default`. Other callers use `?` (`grpc_internal.rs:29, 57, 105, 153, 174, 193, 210`). Go `handler.domainName` is used only for metric/log/quota tags and always continues. Verify that no `?` caller turns an unknown domain into a rejection that Go would accept.
