## Disposition

No narrow code correction is justified in this review. The protocol option is propagated to the Rust persistence session builder as a validation input, but the selected Scylla driver implementation is pinned to CQL v4 and emits its own v4 startup version. The Rust service therefore rejects configured v2/v3 at `rust/crates/cadence-persistence/src/cassandra.rs:751-753`; it does not silently pretend those settings were honored. Go's pinned gocql dependency is `github.com/gocql/gocql v0.0.0-20211015133455-b225f9b53fa1` (`go/go.mod:20`), and Go defaults protocol to 4 (`go/environment/env.go:53-54`, `go/common/persistence/nosql/nosqlplugin/cassandra/gocql/client.go:56-60`) but directly sets `cluster.ProtoVersion` from config. **Production limitation:** configured Cassandra protocol v2/v3 is not compatible with the current Rust driver; achieving parity requires driver protocol support, not a tiny selection patch. v4 is the default and selected path.

## Source-backed comparisons

- Go forwards `ProtoVersion`, credentials, allowed authenticators, keyspace, TLS, timeouts and hosts into gocql in `go/tools/cassandra/cqlclient.go:138-150`; Rust config retains auth allowlist and validates `proto_version` in `rust/crates/cadence-persistence/src/cassandra.rs:727-754`, then configures session hosts/keyspace/timeouts/auth provider in `:804-835`.
- Pinned Rust driver startup behavior: `rust/vendor/scylla-1.9.0/src/client/session.rs:242` identifies the CQL protocol version used for frames and STARTUP; protocol option representation is in `rust/vendor/scylla-cql-2.0.0/src/frame/request/options.rs:27` (`CQL_VERSION`); supported version value is constructed in `rust/vendor/scylla-cql-2.0.0/src/frame/types.rs:269`. The current driver is v4-only, which explains why Rust cannot propagate Go's selectable v2/v3 onto the wire.
- Handshake and registration are owned by the driver: `rust/vendor/scylla-1.9.0/src/network/connection.rs:542` documents initial setup before OPTIONS/STARTUP/REGISTER; `:652` handles STARTUP; `:904` handles auth response; `:1463-1470` constructs REGISTER; `:2352` registers event types. It uses `RegisterV2` in `:24-33`, so the Rust stack has version-specific event registration handling. I found no evidence in this inspection of an application-level skipped OPTIONS/STARTUP or missing register path.
- Rust password auth emits the SASL PLAIN token (`NUL username NUL password`) and checks the configured/default allowlist in `rust/crates/cadence-persistence/src/cassandra.rs:1413-1446`. The Go side only installs `gocql.PasswordAuthenticator` when both user and password are nonempty, and passes `AllowedAuthenticators` in `go/common/persistence/nosql/nosqlplugin/cassandra/gocql/client.go:62-68`. Rust uses the same both-nonempty condition at `:831-836`. No concrete auth mismatch was established; custom challenge-response authenticators are deliberately unsupported by Rust's password session (`:1402-1410`), consistent with password-only provider intent but a deployment constraint if a custom allowlisted authenticator requires challenges.
- Registration/events and reconnect are performed by the Scylla driver's connection lifecycle, not the Matching body codec or metadata fetcher paths. This review made no edits in body codec dispatch/wiring or `metadata/fetching.rs`.
