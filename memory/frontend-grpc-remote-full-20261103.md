# Frontend gRPC remote client: all redirected APIs (2026-11-03)

Branch `t3/frontend-grpc-remote-full` (from master 30b607b0f). Not merged.

## Done
- `cadence_proto::convert::client` (hand written) + `history_in.rs` / `decisions_out.rs` (generated by `rust/tools/generate-grpc-history-in.py`, `generate-grpc-decisions-out.py`, `#[rustfmt::skip]`): internal->proto requests and proto->internal responses, incl. History events and Decisions.
- `frontend_remote_grpc::call` forwards every redirected API over gRPC: 21 workflow/visibility ops, DescribeTaskList, ListTaskListPartitions, 14 worker ops (poll/respond/heartbeat/query), 8 schedule ops. Timestamps use unix nanos like Thrift.
- `GetTaskListsByDomain` is not in the public gRPC WorkflowAPI, so it still returns "not supported" (test `grpc_transport_rejects_operations_absent_from_grpc_api`).
- Unit tests: describe/query/history/list/start families, history events round trip, poll decision round trip, activity/heartbeat/sticky requests, schedule describe.
- Active-active: `active_cluster_for_workflow` now takes Go's empty-policy path (domain active cluster) instead of erroring.
- Gate `tests/gates/run-frontend-two-cluster-gate.py`: new step block `forward-all-grpc` (all-domain forwarding over gRPC: start, signal, describe, show history, list, query). Under selected-apis-forwarding describe/history/list stay local (as in Go), so they are only checked in the all-domain block.
