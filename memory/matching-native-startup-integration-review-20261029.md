## Review and integration fixes

- The changed providers resolve a read-through domain before locking the overlay; filtered values and raw task-list bytes remain passed through. This avoids the overlay/limiter recursive lock and inversion without changing intended Go dynamic-config selection. Each runtime-provider subprocess starts with a cold valid ID, production limited source and enabled limiter clock at its refresh boundary; a domain-filtered assertion makes a successful lookup observable. The 10-second subprocess timeout bounds the deadlock. This is source review only, not an executed test. The separate engine/control paths lack equivalent targeted regressions, and there is no explicitly coordinated two-thread inversion regression; retain these as coverage gaps.
- Pool notification now follows both idle return and discard, outside the mutex. The test-only waiter counter is guarded by the same mutex as the condition wait, so observing it after acquiring the mutex establishes the waiter has released that mutex in the wait. The live test checks timed and unbounded healthy reuse and discarded replacement, and checks open/idle accounting. Its timeout failure previously joined a possibly stuck database thread; the integration removes that join on failure and bounds the whole pool oracle with a 30-second process timeout (plus 5-second kill grace). Connection setup and SQL I/O themselves have no proven wall-clock bound. The gate checks exactly one passing ignored test, records exit status and binary hash, and uses the disposable PostgreSQL instance. A process-level timeout failure is retained as a failure.
- Changed the admission marker so it does not claim membership readiness when the optional lifecycle is absent. Markers are bounded one-time diagnostics, not timing or root-cause proof; errors and the last marker must be interpreted with full logs.
- Added the PostgreSQL pool and membership lifecycle files to the existing optional CI formatting patch list. The new runtime test has obvious formatting exposure. That formatting job modifies the checkout before clippy/tests, so its results cannot validate the immutable source head: obtain and review its patch, commit any required formatting, then run fresh gates on the resulting exact SHA. The normal workspace format check is informational; the dedicated Matching runtime formatting check is enforced.
